## Monster Inspector

`CMonsterInspectorPanel` (`interface/cmonsterinspectorpanel.cpp/h`, owned by `CUIMediator` as `m_MonsterInspector`) is the window opened by the **Monster Inspector skill** — a `SKILL_CREATE_WINDOW` (type 2) skill with `SKILL_POWER == SKILL_WINDOW_MONSTER_INSPECTOR` (50, defined in `gamecommon/skill.h`). It shows the targeted monster's name/level, live HP bar, LIST_NPC stats (ATK/ACC/DEF/M-DEF/Dodge/speeds/EXP), its drop list as item icons, and a rotating 3D model.

- **Purely client-side — no packet, no MP, no aggro by construction.** `CCreateWindowActionSkill::SendSkillActionReq` opens the panel instead of sending anything; `CSkillManager::GetSkillTargetType` special-cases window type 50 to `SKILL_TARGET_OBJECT` (all other window skills stay `SKILL_TARGET_NONE`), and the STB row's class filter 4 (`SKILL_TARGET_FILTER_MOB`) restricts targets to monsters. Cast flow: click a monster once to *target* it (first click targets, second attacks), then use the skill.
- **Drop list** replicates the table walk of the server's `CCal::Get_DropITEM` for display: union of the mob table (`NPC_DROP_TYPE`, only when `NPC_DROP_ITEM > 0`) and the zone-number row of `ITEM_DROP.STB` (`g_TblDropITEM`, already loaded by the client); slot values 1–4 are redirect groups expanding to columns `26+5g … 30+5g`; values > 1000 are `type*1000+no` packed items. Deduped. Hovering an icon shows the **standard inventory item tooltip**: the panel builds a throwaway `tagITEM`/`CItem`, fills a `CInfo` via `CItem::GetToolTip`, and registers it with `CToolTipMgr::RegistInfo` — the tooltip manager draws at the end of `g_itMGR.Update()`, which runs *after* `g_UIMed.Draw()` in `Render_GameMENU`, so registering during the panel draw shows the tooltip the same frame on top of the UI.
- **HP** is read live from the target object each `Update()` (`Get_CharOBJ(idx, false)` so the bar drops to 0 on death) and freezes at the last snapshot when the object despawns; static data stays (the panel keeps working on a dead/gone monster until closed). The object-slot reuse case is guarded by re-checking `Get_CharNO()` against the stored NPC row.
- **3D preview uses the engine's avatar-selection viewport pipeline — no scene insertion, no render-to-texture.** The panel owns a client-only "puppet" clone of the monster model (`g_MOBandNPC` `CCharMODEL` + `::loadModel` with the idle motion + `CreatePART` per body part) that is **never inserted into the scene**. `PuppetDrawInPane()` runs last in the panel's sprite draw: `::flushSprite()` (pushes the already-issued panel sprites — including the double-darkened pane background — under the model), `::setAvatarViewPort(paneRect)` (pane-scoped viewport, z-clear, own orthographic origin-facing camera), `::RenderSelectedAvatar(hModel)` (engine places the model at `(0,0,-1.4)` internal units and calls `update_animation` + `render` itself), `::setDefaultViewPort()`. Because the pipeline has its own fixed camera, world-camera motion (RMB drag etc.) cannot move the preview — the earlier world-anchored version trailed out of the pane during camera rotation. Framing gotchas: engine-*internal* units are meters while `getModelHeight`/interface positions are cm (`ZZ_SCALE_IN/OUT` = ×0.01/×100); the selection camera only has increment APIs (`updateAvatarSelectionCameraLength/Height/Seta`), so the panel keeps a static mirror of the singleton state (defaults 2.15 / −0.10; this panel is the only user) and sets `view_length = modelH_m * 1.2 * paneRatio` (min 0.7), `view_height = −1.4 + modelH_m/2`, plus `Seta += 0.01`/frame for the spin. Device mesh/texture resources are shared by name with the live on-screen monster, so they're already uploaded despite the puppet never entering the scene. Destroy: `clearRenderUnit` → `DeletePART` each → `unloadModel` (no `removeFromScene` — never inserted). **Motion LOD:** `zz_model::apply_motion` has distance-based LOD — `skip_frames` frame skipping driven by `camdist_square` (full rate < 40, up to 10 skipped frames > 200 internal meters) and an interpolated-vs-keyframe-stepped branch gated by `camtarget_distance_square` (which was an *uninitialized* member, only ever written by the shadowmap pass for in-scene shadow-casting models; now ctor-initialized to 0). `RenderSelectedAvatar` calls `zz_model::reset_motion_lod()` (zeroes all three) before `update_animation`, so UI-driven renders always animate at full rate with smooth sampling regardless of what distance state the model inherited — without this the pane visibly mirrored in-world animation LOD.
- **Input** is routed in `CGameStateMain::ProcWndMsgInstant` *before* the summon panel: every LButtonDown on the panel is consumed (close button / drag start — clicks must not leak into the world and attack), mousemove is consumed only while dragging but always feeds hover coordinates for the drop-icon tooltip.
- **Background:** `ID_BLACK_PANEL` has a brightening gradient baked into the sprite's top rows — `DrawFit`-stretching it over a tall rect shows a wide light band at the top, and tiling it as thin strips repeats the bright top row as periodic white lines. `DrawPanelBg` therefore bypasses `DrawFit` and draws with a **cropped source rect** (bottom quarter of the sprite, minus 1 px filter-bleed margin) stretched over the whole rect via `::drawSprite` + geometry-scale transform — one draw, perfectly uniform; the preview pane draws a second layer for extra darkness behind the model.
- Dummy skill data: LIST_SKILL.STB row appended by `scripts/add-monster-inspector-skill.py` (idempotent; prints the skill id — currently **7001**). Learn in game with GM **`/add skill 7001`** (the SKILL branch is in `Cheat_add`, gated by `B_Cheater()`; there is no `/set skill` — `Cheat_set` has no SKILL branch and fails silently, as does an out-of-range skill id when the server still has the old STB cached). Servers must be restarted after the STB append (tables cached at startup) and client data rebaked/deployed.

- **Ranged skill classification:** `IsProjectilePresentedSkillDamage()` decides whether `Recv_gsv_DAMAGE_OF_SKILL` queues a FlatBuffer event for projectile-impact presentation or pushes a payload onto `m_EffectedSkillList` for immediate display. `SKILL_ACTION_IMMEDIATE` with `SKILL_BULLET_NO > 0` (e.g. Twin Shot — a "melee immediate" type whose visual is actually a gun shot) is projectile-presented: the gun/bow fire animation has no action frame 25 hit moment, so `ProcEffectedSkill()` is never called and the bullet impact is the only timing signal. Without this, the skill fires, the bullet reaches the target, no damage digit / hit feedback appears, and the monster dies silently when the server applies the kill.
- **Target-bound continuing skills are NOT projectile-presented:** `SKILL_ACTION_TARGET_BOUND_DURATION` (9), `SKILL_ACTION_TARGET_BOUND` (11), `SKILL_ACTION_TARGET_STATE_DURATION` (13) — e.g. Fire Ring (defense ↓), single-target buffs/debuffs — must be excluded from `IsProjectilePresentedSkillDamage()` regardless of `BULLET_NO`. `BULLET_NO` on these rows points at an effect-graphic ID for the visual ring/aura; no tracked `CBulletDIRECTION` is spawned, so no impact callback ever runs. These skills are drained at the caster's action frame in `cobjchar_actionframe.cpp` case 25 (`SKILL_ACTION_TARGET_BOUND_DURATION` / `_BOUND` / `_STATE_DURATION` → `ProcEffectedSkill()` immediate, without `bProjectileImpact`). Marking them projectile-presented orphans the queued effect-of-skill payload forever: `ProcEffectedSkill()` at action frame skips entries with `bWaitForProjectileImpact=true`, no `AddEnduranceEntity` runs, the debuff visual never appears, and the user reads it as "the skill does nothing" — even though the server side already applied the status.
- **A projectile skill performed with a motion that has no fire frame presents on the melee frame (2026-09-14).** Mob skill motions launch the bullet from action frame 24/34 (`ActionSkill`). A monster whose casting/skill slots were filled with its idle + attack clips (Mukuroji, `pig01`: import-karkia.py's `chr_fill_motions`) never reaches one: its "skill" motion is the attack clip, whose only hit moment is melee frame 21. Before: `ActionInFighting` popped the ProjectileImpact damage event as a plain melee hit (no skill visual), and the caster's queued `GSV_EFFECT_OF_SKILL` payload — the status — waited for an impact that never came and timed out 10 s later; Mukuroji's Flame Heat burn ticked with no icon and no effect, and the timeout produced a burst of `queued presentation miss` lines. `tagMOTION::m_bHasProjectileFireFrame` (computed at load like `m_bHasSkillHitActionFrame`) lets `ActionInFighting` recognise the case — the attacker is a remote caster mid-skill (`m_nDoingSkillIDX`), the skill is projectile-presented, the motion has no 24/34 — and call `Hitted(..., bIsSkillEffect=true)`, which routes through `ProcessSkillHit` (registration consumed, payload applied). Log: `projectile skill presented on melee frame, motion has no fire frame`. The data-side fix (a donor AI that suits a melee-only model) is still the better one for such monsters.
- **A bow/gun fire frame with nothing to fire presents the swing as a melee hit (2026-09-22).** `ActionBow`/`ActionGun` (frames 22/23) only ever called `Add_BULLET` with `Get_BulletNO()`, which is 0 for a bare-handed attacker (`CObjCHAR::Get_BulletNO` reads `WEAPON_BULLET_EFFECT` of the right-hand weapon). The server had applied the swing at frame 0 and queued it on the target as `MeleeHitFrame` (`UsesProjectileAttackPresentation()` is false without a bullet weapon), but a ranged clip carries no frame 21, so nothing consumed the event: no digit, no impact, no HP movement, and the 8 s orphan sweep folded it silently (alpha #2: Hebarn Officer Pazugenti 2685, whose every swing logged `attack motion start` and then only `orphaned damage swept` or `pre-empted swing presented ... attack motion replaced` when its own Ferdinand Stun cast replaced the motion). Frame 21's body is now `PresentNormalAttackHitFrame()`, and `PresentFirelessRangedFrame()` calls it from 22/23 when `Get_BulletNO()` is 0 and the attacker is not the local avatar (with no ammo the server never runs its attack). Frames 32/33 take `NPC_ATTACK_SOUND` for a bare-handed mob like 31 does. Log: `fireless ranged frame presented as melee hit`. The Lich01 attack clip itself is also wrong in our tree -- 23/33 in the RoseZA/667/Evo lineage our April copy came from, 21/31 in Jrose/QQ/ruff/titan/tsuki -- and `scripts/fix-zmo-attack-frames.py` rewrites the two trailer shorts; its `--audit` lists the 36 rows (Candle Ghost, Bebeg, Sikuku Tiger Captain, the Oro vassals ...) that sit on a bullet-less ranged clip in every dump and now land through the fallback. Note the skill damage in that report was never lost: `GSV_DAMAGE_OF_SKILL` presents through the Immediate pop, just ~2 s after the packet.
- **Server-client `presentation_kind` agreement:** server `CObjCHAR::IsProjectilePresentedSkill` and client `CObjCHAR::IsProjectilePresentedSkillDamage` both call the shared `Rose::Combat::is_projectile_presented_skill(skill_type, bullet_no)` helper. Keep wrappers thin: `05/06` are projectile-presented, `03/19` are projectile-presented only with a bullet id, and target-bound `09/11/13` are never projectile-presented even if `BULLET_NO` is set.

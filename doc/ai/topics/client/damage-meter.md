## Damage Meter ("/dps")

Client-only DPS meter fed by the authoritative combat event stream. **Zero combat-display behavior changes** — the whole feature is a read-only observer. (Phases 2/3 added two wire fields, `DamageEvent.skill_id` and `source_attacker_id`, as display metadata; nothing in presentation reads them.)

- **Data core** (`gamedata/CDamageMeter.cpp/h`, singleton): fed by a single tap at the end of `CObjCHAR::PushCombatDamageEvent` — the one chokepoint every damage source funnels through exactly once (FlatBuffer `CombatSwing`/`DamageEvent` + all legacy `GSV_DAMAGE` / `GSV_DAMAGE_OF_SKILL` conversions). The tap copies what it needs and never mutates the event, the queue, or presentation state. Recording at queue time is deliberate: damage whose animation is later discarded/folded (hard-control interrupts, drain-on-death) was still real server damage and must count.
- **Attribution field:** `Rose::Combat::DamageEvent.skill_id` (client struct) mirrors the phase-2 wire field `DamageEvent.skill_id` in `combat.fbs` (0 = normal attack/unknown; **display metadata only — presentation logic on both sides must never branch on it**). Sources, in priority order: exact from the wire (`to_client_damage_event`; server threads the skill through `Give_DAMAGE(..., kind, nSkillIDX)` → `Send_combat_damage_event` → `build_damage_event_packet` — currently `Skill_START` SKILL_TYPE_06 passes `Get_ActiveSKILL()` and the shield counter passes `nShieldSKILL`); exact from legacy `GSV_DAMAGE_OF_SKILL` in `ConvertDamageOfSkillToDamage` (`m_nSkillIDX`); heuristic fallback in `recv_damage_event` only when the wire field is 0 (`ProjectileImpact` events → caster's `m_nToDoSkillIDX`/`m_nActiveSkillIDX`). `CombatSwing` intentionally keeps 0 = normal attack. Kind-based labels fill the gaps: `StatusTick` → "DoT", `Immediate` w/o skill → "Other".
- **Classification at record time** (object slots are recycled — names/party membership can't be resolved later): cart/castle-gear attacker **and defender** fold to the rider — use `IsPET()`, which covers `OBJ_CART` and `OBJ_CGEAR` (castle gear is its own object type; an `== OBJ_CART` check silently dropped all castle-gear damage — first in-game regression found). `CObjCastleGear` derives from `CObjCART`, so the `GetParent()` cast is valid for both. Then: self vs own summon (`GetSummonedMobList` by server index) vs party member (`CParty::IsPartyMember(Get_ServerObjectIndex(...))`) vs other. Stranger-vs-mob spectator samples are dropped; everything hitting the avatar (or its mount) is kept. Party members' damage works out of the box because `send_packet_nearby` broadcasts combat events to the 9 surrounding sectors — no extra packets.
- **Dedup guards:** event-key ring `(event_id, attacker, defender)` — synthetic legacy ids live in separate counters and can collide with server ids, hence the composite key — plus a per-defender lethal window (2 s): legacy + FlatBuffer paths can each announce the same death but a defender dies once.
- **Segments:** a fight ends after 6 s without samples (`kIdleGapMs`); the panel keeps showing the last fight while idle. Aggregation is rebuilt on demand (`BuildSnapshot`, capped sample ring) — the view layer holds no state of its own.
- **UI** (`interface/CDamageMeterPanel.cpp/h`, owned by `CUIMediator` as `m_DamageMeterPanel`): direct-draw overlay in the `CSummonInfoPanel`/`OverlayPanelUtil` style (no XML). Views: Damage Done (self + party ranking, self+pets folded into one row), My Skills, Damage Taken; header buttons `[>]` cycle / `[R]` reset / `[X]` close; footer shows the biggest hit. Toggled by the **local** `/dps` chat command (`CChatDLG::SendChatMsg` intercepts before any send; `/dps reset` clears data). Input routed in `CGameStateMain::ProcWndMsgInstant` between the Monster Inspector and the summon panel, matching draw order. Layout/style constants are grouped in an anonymous namespace at the top of the panel cpp for easy modding.
- **Credit vs. attacker (`source_attacker_id`, phase 3):** the wire's `source_attacker_id` (server index → client index in `to_client_damage_event`) is who the meter *credits* when it differs from `attacker_id`: DoT casters (status ticks keep the victim in `attacker_id` for presentation; poison ticks pass the stored speller + skill) and summon owners (server auto-resolves in `Send_combat_swing`/`Send_combat_damage_event`). In the meter: source ≠ attacker on a non-StatusTick event ⇒ pet sample (own pets → self row + "Pets" skill label; party pets → fold into the party member's row); on a StatusTick it's caster attribution, not a pet. Incoming DoTs show the caster's name; "DoT / Status" remains only for unattributed self-ticks. The own-summon-list check stays as fallback for events without a wire source.
- **Alternative RmlUi view:** with `[VIDEO] RMLUI=1` the `/dps` command opens a CSS-authored meter instead (see "RmlUi UI Layer"). It is a second consumer of `BuildSnapshot()` — `CDamageMeter` itself is unchanged, and the legacy panel remains the default.
- **Known limits:** party summons' *legacy-path skill* damage (GSV_DAMAGE_OF_SKILL from a summon) still isn't owner-credited — only FlatBuffer swing/event paths carry `source_attacker_id`; party members are only metered while their fights are within your ~1-sector broadcast range (by design — the meter shows the fight around you); no healing meter (heals arrive as bare stat sync). Possible later: combat-log file export for external tools.
